# Feature Specification: Repository Document Consistency

**Feature Branch**: `feature/doc-consistency`

**Created**: 2026-09-27

**Status**: Draft

**Linear issue**: CHE-6

**Input**: Section 2, "Repository document consistency", of the brief
`briefs/2026-09-27-linear-and-documents.md` outside the repository (in the
`briefs/` folder beside the worktrees). It records these decisions of the user,
made on 2026-09-27:

1. No part of a target document is human-written. Every part is either a
   mechanical region or an agent region. No protection for human prose, no
   approval trailers for human edits and no edit locks are designed.
2. Mechanical regions are marked in the documents and name their source (for
   example the task list in `deno.json`); they are regenerated when the source
   changes. Everything else is an agent region. Backfire, the code plugin's
   judgment server from `feature/005-backfire-mcp`, judges whether a change
   made an agent region wrong (`backfire_verify`) and whether a new part can
   become a mechanical region (`backfire_classify`). Judging every sentence
   afresh on each change, without markers, was rejected.
3. Mechanical regions are checked against their sources in `deno task verify`,
   offline and deterministically. Backfire judgments run before the `develop`
   merge review, not in `verify`, because backfire makes paid network calls and
   `verify` also runs in the feature-finish hook.
4. Targets: `README.md`, `docs/architecture.md` and the plugin documents this
   project wrote itself. The root `AGENTS.md` and the constitution are excluded
   from automatic updates; drift found there is only reported to the user.
   `specs/` records, vendored skills (those with `UPSTREAM.md`) and the
   generated reference documents are excluded.
5. Candidate tools, confirmed in [research.md](research.md): Cog (`cogapp`),
   markdown-it-py and lychee; Vale only when a need shows.
6. Tools are chosen so the Wiki document consistency feature (010) can reuse
   them. Python tools use uv like backfire and live in `packages/`; external
   programs are pinned and checked by `deno task doctor`, as Quarto is.
7. The specification is written now; implementation starts after
   `feature/005-backfire-mcp` merges into `develop`.

`docs/reference/commands.md` and `docs/reference/plugins.md` stay generated by
`scripts/docs.ts` and checked by `deno task docs:check`; this feature changes
neither and does not grow `scripts/docs.ts`.

## User Scenarios & Testing *(mandatory)*

The actors are the coding agents (Claude Code and Codex) that change the
repository, the main agent that prepares a feature's `develop` merge review,
and the user, who owns the repository and reads drift reports.

### User Story 1 - Verification refuses a stale mechanical region (Priority: P1)

An agent changes a source that a mechanical region is derived from, such as a
task in `deno.json`, and forgets the document. `deno task verify` fails, names
the document and the region, shows the difference, and names the command that
regenerates it. After the agent runs that command, verification passes. The
check never changes a file and never uses the network.

**Why this priority**: It is the only part that runs on every verification and
blocks a feature finish, so it catches the most common drift at no cost.

**Independent Test**: In a scratch copy of the repository, change a source of
a mechanical region, run the check, confirm it fails without changing any
file, run the regeneration command, and confirm the check passes.

**Acceptance Scenarios**:

1. **Given** every mechanical region matches its source, **When** the check
   runs, **Then** it passes and no file changes.
2. **Given** a source changed and its region did not, **When** the check runs,
   **Then** it fails, names the document and region, shows the difference and
   the regeneration command, and no file changes.
3. **Given** a stale region, **When** the agent runs the regeneration command,
   **Then** only the region's text changes, the rest of the document is
   byte-identical, and a second run changes nothing.
4. **Given** a mechanical region whose marker does not name an existing source
   or does not call a registered generator, **When** the check runs, **Then**
   it fails and names the region.
5. **Given** a target document links to a local file or heading that does not
   exist, **When** the check runs, **Then** it fails and names the link.
6. **Given** the machine has no network, **When** the check runs, **Then** it
   gives the same result as with a network.

---

### User Story 2 - Agent regions are judged before the `develop` merge review (Priority: P1)

Before a feature's `develop` merge review, the main agent runs one offline
command that splits the target documents into agent-region units (sections
and paragraphs with line numbers) and prepares backfire requests: each unit as
a claim, checked against the feature's changes as evidence. The main agent
sends them to `backfire_verify`. For each unit the change contradicts, or that
backfire flags for review, the agent corrects the target document before the
review. New units added by the feature go to `backfire_classify`, which says
whether each could become a mechanical region.

**Why this priority**: Agent regions hold most of the text; without this step
nothing notices when a change makes them wrong.

**Independent Test**: On a scratch branch that renames a task mentioned in
`docs/architecture.md`, run the preparation command and confirm the affected
paragraph is among the claims with its line numbers and the diff is the
evidence; send the request to backfire and confirm the paragraph comes back
`contradicted` or `review`.

**Acceptance Scenarios**:

1. **Given** a feature branch, **When** the main agent runs the preparation
   command, **Then** it prints, without network or file writes, backfire
   request arguments whose claims are the agent-region units of every target
   and whose evidence is the feature's changes against its merge base with
   `develop`, each unit identified by document, heading path and line range.
2. **Given** the same branch and the same files, **When** the command runs
   twice, **Then** both outputs are byte-identical.
3. **Given** mechanical regions in a target, **When** the command splits it,
   **Then** no mechanical-region text appears in any claim.
4. **Given** the feature added units to a target, **When** the command runs,
   **Then** it also prints `backfire_classify` arguments for those units, with
   the classes "mechanical candidate" and "agent region".
5. **Given** units or evidence larger than backfire accepts in one call,
   **When** the command runs, **Then** it splits them into several requests,
   each within the limits, and loses no unit.
6. **Given** backfire judged a unit `contradicted` or flagged it for review,
   **When** the main agent finishes the step, **Then** the unit is corrected in
   the same feature before the merge review, or the agent records why it stands.
7. **Given** `deno task workflow` is in REVIEW mode for a feature, **When** an
   agent reads its instructions, **Then** they include this step before the
   `develop` merge review.

### User Story 3 - Drift in `AGENTS.md` and the constitution is reported, not fixed (Priority: P2)

The root `AGENTS.md` and the constitution change only by the user's decision.
In the same step as User Story 2, their paragraphs are judged against the
feature's changes and a deterministic audit looks for stale paths, conflicts
and duplicates in them. The main agent reports what it finds to the user and
changes neither file.

**Why this priority**: These files govern every agent, so drift there matters,
but the user decided they are never updated automatically.

**Independent Test**: On a scratch branch that removes a script `AGENTS.md`
names, run the step and confirm the report names the line and neither file
changes.

**Acceptance Scenarios**:

1. **Given** a feature that makes an `AGENTS.md` or constitution statement
   wrong, **When** the step runs, **Then** the report names the file, line and
   reason, and both files are unchanged.
2. **Given** the step ran, **When** the user reads the report, **Then** each
   finding says whether it came from a deterministic audit or a backfire
   judgment, and deterministic findings cite the evidence (the missing path or
   the two conflicting lines).

---

### User Story 4 - A reader and feature 010 can find the region model (Priority: P3)

A reader at HEAD opens `docs/architecture.md` and learns what a mechanical and
an agent region are, how to add a mechanical region, which documents are
targets, and when each check runs. Feature 010 (Wiki document consistency)
reuses the same region model and components without redefining them.

**Why this priority**: It has no effect of its own, but without it later
agents rely on memory and feature 010 would redefine the model.

**Independent Test**: Read the documentation section and the component's
interface, and add a mechanical region to a scratch document by following them.

**Acceptance Scenarios**:

1. **Given** `docs/architecture.md`, **When** a reader looks up document
   consistency, **Then** it describes the region model, the target list, the
   offline check, the pre-review judgment step and what stays manual.
2. **Given** the shared component, **When** feature 010 adds its own targets
   and generators, **Then** it needs no change to the component's region
   rules, unit splitting or request preparation.

### Edge Cases

- A mechanical region's code tries to read the network, write another file or
  depend on the time or the machine: the region is refused by review and the
  check's tests; a region's output depends only on its named source files.
- A target document quotes the marker syntax, for example to explain it:
  Cog would treat the quote as a real region, so target documents link to the
  contract instead of quoting markers, and the check reports such a quote as a
  malformed region.
- A mechanical region sits inside a list: markers still work, and unit
  splitting still leaves the region out.
- Markers are unbalanced (a start without an end, or nested regions): the
  check fails and names the line.
- A target document is deleted or renamed: the target list must change in the
  same commit, or the check fails.
- A target has no mechanical region: it is still a target; all of it is agent
  region, and link checks still apply.
- A source of a mechanical region is missing: the check fails and names it.
- An agent region contains a link to an external URL: the offline check does
  not follow it, and does not fail on it.
- The feature's changes touch no file at all apart from the target documents:
  the judgment step still judges the edited units against the diff.
- Backfire is not installed or not configured: the preparation command still
  works; the main agent reports that the judgment step could not run instead of
  skipping it silently.
- Evidence would contain private records or secrets: the repository holds none
  by rule, and the preparation command sends only repository diffs and target
  documents; Wiki raw evidence is out of scope here.

## Requirements *(mandatory)*

### Functional Requirements

**Region model (decisions 1 and 2)**

- **FR-001**: Every part of a target document MUST be either a mechanical
  region or an agent region. A mechanical region MUST be delimited by markers
  in the document, and its marker MUST name the generator and every source
  file its text is derived from. Everything outside mechanical regions is an
  agent region, without markers.
- **FR-002**: A mechanical region's text MUST depend only on its named
  sources: the same sources give byte-identical output, and generation uses no
  network, clock, environment-specific value or file write other than the
  region itself.
- **FR-003**: One command MUST regenerate every stale mechanical region in
  place, changing nothing outside the regions, and a second run MUST change
  nothing.
- **FR-004**: The target list MUST be one committed list: `README.md`,
  `docs/architecture.md`, `docs/backfire.md` and the plugin documents this
  project wrote itself.
  `AGENTS.md` and the constitution MUST be listed as report-only. `specs/`,
  vendored skills (with `UPSTREAM.md`) and `docs/reference/` MUST NOT be
  listed.

**Offline check (decision 3)**

- **FR-005**: `deno task verify` (through `deno task check`) MUST fail when a
  mechanical region differs from its generator's output, when a marker is
  malformed or names a missing source or unknown generator, or when a target
  links to a missing local file or heading.
- **FR-006**: The check MUST NOT write any file or the Git index and MUST NOT
  use the network, and its failure message MUST show the difference and the
  regeneration command.
- **FR-007**: `deno task doctor` MUST fail when a pinned tool this feature
  adds is missing or has another version, as it does for Quarto and
  git-flow.

**Judgments before the merge review (decisions 2 and 3)**

- **FR-008**: An offline, deterministic command MUST split target and
  report-only documents into agent-region units (heading path, block text,
  first and last line) and print ready-to-send arguments for
  `backfire_verify` (units as claims, the feature's changes against its merge
  base with `develop` as evidence, one evidence item per changed file,
  leaving out the judged documents and files matching the configured
  `evidence_exclude` globs) and for `backfire_classify` (units the feature
  added to target documents, as items).
- **FR-009**: The command MUST split requests to stay within backfire's input
  limits and MUST keep every unit in exactly one request.
- **FR-010**: The judgment step MUST run before each `develop` merge review
  and MUST NOT run inside `deno task verify` or the feature-finish hook.
- **FR-011**: Units of target documents that backfire judges `contradicted` or
  flags for review MUST be corrected before the merge review or have the
  reason recorded; units of `AGENTS.md` and the constitution MUST only be
  reported to the user.
- **FR-012**: `deno task workflow` in REVIEW mode MUST print the judgment step
  as part of preparing the `develop` merge review.

**Report-only documents (decision 4)**

- **FR-013**: A deterministic audit of `AGENTS.md` and the constitution for
  stale paths, conflicting rules and duplicates MUST run in the judgment step
  and report findings with file, line and evidence, without changing any file.

**Reuse and documentation (decisions 5 and 6)**

- **FR-014**: Region parsing, unit splitting, request preparation and the
  check MUST live in one reusable package under `packages/`, so feature 010 can
  use them with its own target list and generators. Its library functions
  MUST accept target globs, a root other than the repository with a generator
  path outside it, and evidence the caller supplies per group of units.
  Feature 010's research asked for these on 2026-09-28.
- **FR-015**: Repository-specific generators and the target list MUST live
  outside that package, in repository automation.
- **FR-016**: `docs/architecture.md` MUST describe the region model, how to
  add a mechanical region, the target list, the check, the judgment step and
  what stays manual; the documentation MUST itself follow the region model.
- **FR-017**: This feature MUST NOT change `scripts/docs.ts` or `deno task
  docs:check`, and MUST NOT edit `docs/reference/` by hand. The tasks it adds
  to `deno.json` reach `docs/reference/commands.md` only through `deno task
  docs:generate`, which that file's generator requires for `docs:check` to
  pass (SC-006).

**Order (decision 7)**

- **FR-018**: Implementation MUST start only after `feature/005-backfire-mcp`
  has merged into `develop`, and MUST use backfire's tools as that merge
  defines them.

### Key Entities

- **Target document**: A repository document the feature keeps consistent.
  Attributes: path, mode (updated or report-only).
- **Mechanical region**: A marked span of a target. Attributes: document,
  start and end lines, generator, source files, current text.
- **Agent region**: A maximal span of a target outside mechanical regions.
- **Unit**: A block of an agent region that backfire judges. Attributes:
  document, heading path, block kind (heading, paragraph, list item, table,
  code), first and last line, text, whether the feature added it.
- **Judgment request**: Arguments for one backfire tool call. Attributes:
  tool, claims or items with unit identifiers, evidence items with file paths.
- **Drift finding**: A reported problem. Attributes: document, line, source
  (deterministic audit or backfire), evidence, action (fixed, reported or
  stands with a reason).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: In the automated tests, 100% of stale, malformed and
  missing-source cases fail the check, every passing case passes, and no case
  changes a file or opens a network connection.
- **SC-002**: The check adds no more than 5 seconds to `deno task check` on the
  development machine.
- **SC-003**: Regeneration run twice on the same sources changes nothing the
  second time, in every test case.
- **SC-004**: The preparation command gives byte-identical output for the same
  inputs and covers every agent-region unit of every target exactly once.
- **SC-005**: On a scratch branch that makes one paragraph of
  `docs/architecture.md` wrong, backfire flags that paragraph (`contradicted`
  or review) in each of three runs.
- **SC-006**: `deno task verify` passes on the final feature tree, and
  `deno task docs:check` still passes unchanged.

## Assumptions

- The brief's tool list is a set of candidates; [research.md](research.md)
  records the versions, licenses and fit confirmed from primary sources, and
  where they changed the brief's assumptions.
- The main agent, not a script, calls backfire's MCP tools, so no new
  credential handling or network code is added to the repository; backfire's
  own records keep what was sent.
- Evidence for `backfire_verify` is the repository diff only; the repository
  holds no private records by constitution rule.
- Plugin documents "this project wrote itself" are those not copied or
  adapted from an upstream source; today there are none (see Clarifications).
- Vale is not added; no terminology or style need has shown yet.
- Code maps (Aider's repository map, RepoMapper, Serena) are out of scope;
  agents' on-demand search is enough at this repository's size.
- `feature/005-backfire-mcp` and its worktree are not touched.
