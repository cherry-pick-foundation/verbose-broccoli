## Gate disposition

Every free-text path and ordinary ID/syntax string path in the argument table is swapped, including recursive context keys. Three schema-pattern ID paths fail closed on identifiers and otherwise stay unchanged: decide candidates[].id, extract fields[].id and audit records[].id (D4). Extract fields[].pattern is a regex-source argument, so it is swapped; it is not a constrained schema field. Paths are metadata, never filesystem instructions. Flags preserve valid syntax or the masked call rejects. All numeric/boolean arguments remain unchanged; open-context numeric identifiers require the policy in privacy-gate.md before real rollout.

Every result free-text path, caller ID, probability/summary key, model/provider metadata string and arbitrary usage leaf is traversed for restoration (D2). Fixed tool names, enums, rubric names, numbers, booleans and null remain unchanged. Restoration tokens cannot collide with these fixed strings. Every `content[].text` block is processed, including JSON escape decoding and plain errors; walk structured_content/meta if present. Never assume usage is numeric. A result field absent in a variant is not invented.

Known ID sanitization can erase a masked name: dist/lib.js:22-43 retains ASCII, truncates and falls back. The gate must reject an unsafe sensitive ID before forwarding if its token cannot survive; exact restoration is not claimed for arbitrary upstream transformations. Test that limit as well as successful ordinary ID restoration.

No outputSchema is published. The handshake advertises tools only; unsupported direct resources/templates/prompts returned -32601 in W1 raw-discovery.json. The wrapper additionally blocks these surfaces so an upstream upgrade cannot open a bypass. Unexpected tool/schema changes stop acceptance for review (W1:101-111; D3).

### Result field map

Paths in this table are relative to the JSON parsed from `content[].text`, not to the MCP result envelope. **The outer `content[].text` itself always needs restoration**, including error replies. There is no structuredContent in the upstream handler surface. The table includes string metadata and identifiers even where they are not prose.

Common fields on normal outputs: `tool` is a fixed tool name; `provider` is a route identifier (`openrouter` for the selected route, `none` for local-only extraction); `model` is a configured/model identifier string. `usage.input_tokens` and `usage.output_tokens` should be numbers but the OpenRouter route does not validate their types. They can contain arbitrary strings or nested objects from the response. Restore recursively there too. `usage` is null for local-only extraction. ## Controlled compatibility coverage

The all-tool fixture uses valid upstream schemas and deterministic local fetch responses; it does not replace schemas with invented echo-only tools. It captures provider requests and actual MCP results for all 12 tools, including per-file review/gate, no-match extraction, invalid regex, invalid mode and nested usage. A separate echo fixture proves recursive restoration in supported text/structured/meta fields. Assertions check every path above, key collisions, constrained IDs, preserved enums/numbers and continued service after refusal. W1's 18 synthetic MCP calls/15 intercepted provider requests provide a shape baseline, not final proxy or model-quality acceptance.
