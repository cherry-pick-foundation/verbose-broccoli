# Security delta review: mise 2026.9.17

Reviewed 2026-09-30. Difficulty: difficult.

## Scope and method

This report covers only the change from `v2026.9.16` to `v2026.9.17` in
the supplied clone. References of the form `tag:path:line` name the file and
line in that tag, not the clone's detached working tree.

I inspected the complete source diff, `Cargo.toml`, `Cargo.lock`,
`settings.toml`, `registry/`, `vendor/aqua-registry/`, and the changed
release, build, and packaging files. The showreel media and documentation-only
content were excluded because they do not execute during installation or use.
I did not run tests, builds, install scripts, or downloaded tools.

Two protocol deviations prevent this run from being strictly read-only:

- One advisory-query retry used bare `python3`. It resolved to
  `~/.local/share/mise/shims/python3`, invoked the installed mise 2026.9.17,
  and stopped because the clone's `mise.toml` was untrusted. It did not run
  a test, a build, or an install, and it produced no query result. All later
  source-review commands used absolute system paths.
- An earlier plain `git status` likely refreshed the clone's `.git/index`
  metadata. No source or untracked file changed. The final read-only status was
  `## HEAD (no branch)`, but the index refresh itself violated the requested
  repository boundary.

## Verdict

**The delta adds no new high or medium finding. Zero high and four medium
findings stand for the planned use.** M-1 got better; M-2, M-3, and M-4 stayed
the same. The release also adds two low-risk opt-in execution paths.

The planned settings still apply: `paranoid = true`,
`locked_verify_provenance = true`, `use_versions_host_track = false`,
`node.gpg_verify = true`, and `github.gh_cli_tokens = false`. Continue using
direct content-bound trust, keep `github.credential_command` unset, review
`mise.lock`, and install with `--locked`. Also leave
`not_found_auto_install_registry = false` and do not add a tool-level
`postinstall` option unless its command is reviewed as code.

Finding counts for 2026.9.17: **0 high, 4 medium, 2 low**.

## Findings

### M-1 — Project diagnostics still execute trusted shell commands

**Severity: medium. Status: better, not resolved.**

Paranoid mode now refuses to turn `--yes`, `MISE_YES`, or a similar
automatic answer into trust. The new condition requires
`settings.yes && !settings.paranoid`:
`v2026.9.17:src/config/config_file/mod.rs:518-575`. Paranoid trust remains
bound to the file's SHA-256 content:
`v2026.9.17:src/config/config_file/mod.rs:630-638`,
`v2026.9.17:src/config/config_file/mod.rs:852-863`, and
`v2026.9.17:src/config/config_file/mod.rs:958-966`.

The diagnostic command remains unsandboxed. It loads checks from active config
files, prepares the project environment without installing tools, and executes
each configured command through the selected shell:
`v2026.9.17:src/cli/doctor/project.rs:15-20`,
`v2026.9.17:src/cli/doctor/project.rs:120-161`, and
`v2026.9.17:src/cli/doctor/project.rs:220-262`.
`trusted_config_paths` still bypasses the content hash:
`v2026.9.17:src/config/config_file/mod.rs:599-605`.

Mitigation: keep paranoid mode on, trust only the exact reviewed
`mise.toml`, avoid `trusted_config_paths` and monorepo trust, and review
every `[doctor.checks]` command, shell, and directory.

### M-2 — Lockfile provenance is still trusted by default

**Severity: medium. Status: stayed the same.**

The Aqua and GitHub verification files did not change:

```text
$ GIT_OPTIONAL_LOCKS=0 /usr/bin/git diff --quiet v2026.9.16 v2026.9.17 -- \
    src/backend/aqua.rs src/backend/github.rs
$ echo $?

```

Aqua still reuses recorded non-SLSA provenance unless forced and still skips
provenance detection when the lock has only a checksum:
`v2026.9.17:src/backend/aqua.rs:2702-2757`. GitHub has the same behavior:
`v2026.9.17:src/backend/github.rs:1734-1790`.
`locked_verify_provenance` still defaults to false and its documentation says
the lock is trusted by default: `v2026.9.17:settings.toml:1751-1768`.
Paranoid mode or the planned setting forces verification:
`v2026.9.17:crates/mise-settings/src/accessors.rs:45-47`.

The delta only adds warnings for lockfile formats that have been superseded for
six months: `v2026.9.17:src/lockfile.rs:82-180`. Those warnings do not change
URL, checksum, signature, or provenance verification.

Mitigation: keep `locked_verify_provenance = true`, review every URL,
checksum, and provenance change, and use `--locked`.

### M-3 — Three planned binary paths still lack required publisher identity

**Severity: medium. Status: stayed the same.**

The only embedded Aqua registry addition is `jdx/packslip`; the planned uv,
lychee, and Vale entries did not change. The current entries require a GitHub
attestation for uv, no checksum or provenance stanza for lychee 0.24.2, and a
checksum but no attestation stanza for Vale 3.23.0:
`v2026.9.17:vendor/aqua-registry/registry.yml:17396-17422`,
`v2026.9.17:vendor/aqua-registry/registry.yml:65314-65330`, and
`v2026.9.17:vendor/aqua-registry/registry.yml:101799-101814`.
Aqua only detects provenance named by registry metadata:
`v2026.9.17:src/backend/aqua.rs:1340-1365`.

The generic GitHub backend still tries GitHub attestations when available but
accepts an asset for which none is found:
`v2026.9.17:src/backend/github.rs:1279-1358` and
`v2026.9.17:src/backend/github.rs:1760-1797`.

### M-4 — A Node lock entry still bypasses the normal OpenPGP check

**Severity: medium. Status: stayed the same.**

The Node backend did not change. A matching lock URL and checksum still prevent
`get_checksum` from running:
`v2026.9.17:src/plugins/core/node.rs:262-314`.
`get_checksum` downloads `SHASUMS256.txt` and normally verifies its
OpenPGP signature for Node 2x releases, but a signature HTTP 404 only warns:
`v2026.9.17:src/plugins/core/node.rs:358-408`.
Lock generation still reads the unsigned checksum manifest directly:
`v2026.9.17:src/plugins/core/node.rs:870-930` and
`v2026.9.17:src/plugins/core/node.rs:961-971`.

Mitigation: keep `node.verify = true` and `node.gpg_verify = true`.
Independently authenticate the Node 24 checksum before approving its lock
entry, or omit Node from the lock until mise authenticates it on that path.

### L-1 — An opt-in postinstall can now run on every install

**Severity: low. New in this delta.**

A tool option may now set
`postinstall = { run = "...", when = "always" }`:
`v2026.9.17:src/toolset/tool_version_options.rs:379-387` and
`v2026.9.17:src/toolset/tool_version_options.rs:484-503`.
When the tool is already installed, `mise install` runs that shell command
instead of skipping the request:
`v2026.9.17:src/backend/mod.rs:3898-3914`.
Safe mode rejects postinstall options:
`v2026.9.17:src/toolset/tool_request.rs:445-460`.

The planned config contains version pins only, so this path is not reached.
`--locked` does not make a configured postinstall inert. Treat any future
postinstall value as executable code and re-trust the changed config.

### L-2 — A missing command can opt into an unpinned global install

**Severity: low. New in this delta.**

The new `not_found_auto_install_registry` setting defaults to false:
`v2026.9.17:settings.toml:2154-2166`. If enabled, the command-not-found
handler selects a unique registry provider, installs its latest version, and
calls the global `mise use` path:
`v2026.9.17:src/cli/hook_not_found.rs:26-48` and
`v2026.9.17:src/cli/use.rs:234-247`. This can write global config and install
an unpinned tool after a command typo.

The planned shims do not reach this new path while the setting remains false.
Keep it false.

`v2026.9.17:src/cli/version.rs:311-372` and

`v2026.9.17:src/cli/version.rs:171-185` and

## Final decision

**mise 2026.9.17 has 0 high findings and 4 medium findings that stand for this
planned use.** No high or medium issue was introduced by the delta. The planned
settings remain applicable and paranoid mode is stronger in this release.

The settings do not close the three external publisher-identity gaps or
authenticate a Node checksum copied into the lock. Those controls still need
the independent actions described in M-3 and M-4.
