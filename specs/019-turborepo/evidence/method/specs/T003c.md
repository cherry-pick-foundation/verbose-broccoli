# CHE-32 task T003c (follow-up to T003): docs help collection with a symlinked node_modules

**Target**: `scripts/docs.ts`, the help-collection spawn you rewrote at the selected sites S048/S058.

**Change**: `npm run test:docs` fails all 14 tests with "scripts/doctor.ts: Help collection failed (exit 1, stderr 991 bytes)". Cause, reproduced by the coordinator: the test fixture (`scripts/docs_test.ts:57`) links `<repo>/node_modules` to the real repository's `node_modules`, and the spawned Node process gets `--allow-fs-read=<repo>/node_modules` only; Node checks the resolved target, so loading `@deno/shim-deno` fails with "Access to this API has been restricted. Use --allow-fs-read to manage permissions." Adding the resolved path of `<root>/node_modules` to the read scopes made `doctor.ts --help` work in the reproduction. Make the help spawn grant read access to the resolved paths of the scopes it already grants (at least `node_modules`), without widening them otherwise. (Node's SecurityWarning is now silenced for npm-run processes through `.npmrc` `node-options`; direct `execFile(process.execPath, ...)` children do not see that, so if a help child still writes that warning to stderr, add `--disable-warning=SecurityWarning` to that spawn's arguments too.)

**Constraints**: Only `scripts/docs.ts` at the selected help-spawn sites, plus an addendum to your report. Do not edit tests.
